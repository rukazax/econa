## Наиболее полезные референсы

| Референс | Применение | Существенное ограничение |
|---|---|---|
| [OSEO](https://github.com/PhilRWA/OSEO-Open-Source-Electric-Outboard-Motor) | Компоновка небольшого подвесного привода, доступность деталей | README описывает 36 В и около 900 Вт; масштаб не соответствует океанскому HPM-приводу |
| [MAM17](https://github.com/ZeniteSolar/MAM17) | Сравнение управления моторным модулем и обмена по CAN | В выбранных исходниках один PWM, аппаратные файлы chopper; трёхфазный FOC для HPM не подтверждён |
| [MCC18](https://github.com/ZeniteSolar/MCC18) | Модульный MPPT и методика диагностики | Выходные испытания в README ограничены 50 В; это не подтверждение зарядки нашего банка |
| [DieBieMPPT](https://github.com/DieBieEngineering/DieBieMPPT) | Изучение реализации MPPT и CAN | Автор прямо обозначает силовое железо как непроверенное; работа вспомогательных цепей не доказывает MPPT под нагрузкой |
| [Swiss Solar Boat MCU](https://github.com/Batou1406/MCU-SwissSolarBoat) | Архитектура CAN-координатора и журнала | Архивный проект; вспомогательное питание 24 В, преобразователь описан для 20–28 В, не для тяговых 72 В |
| [boat19](https://github.com/ZeniteSolar/boat19) и [CAN_IDS](https://github.com/ZeniteSolar/CAN_IDS) | Декомпозиция систем и формальное описание сообщений | README CAN_IDS отмечает несколько экспортёров как незавершённые. Идентификаторы не назначены для ECONA |
| [DeepPlankter](https://github.com/majianjia/DeepPlankter) | Две цепи питания автоматики и измерение энергии | В примере два банка 2S; навигационная прошивка и связь опубликованы не полностью. Не силовая схема для HPM |
| [FEEMS](https://github.com/SINTEF/FEEMS) и [RunFEEMSSim](https://github.com/SINTEF/FEEMS/tree/main/RunFEEMSSim) | Временной энергетический баланс, потери, отдельный сценарий с ДГУ | Расчётные Python-пакеты, не физический контроллер. Снимок feems 0.18.1 требует Python ≥3.10 и <3.13 |
| [MarPowSim](https://github.com/NTNU-MCS/MarPowSim) | Модели компонентов и переходных процессов энергетики | Библиотека Matlab/Simulink; примеры README требуют MATLAB R2013a, ACADO и MSS. Работа в Octave не подтверждена |

Общую лицензию не присваивать всей подборке. Metadata GitHub содержит GPL-3.0, MIT, Apache-2.0 и неопределённые записи. FEEMS объединяет пакеты с разными лицензиями; перед заимствованием кода, схем и PCB проверять конкретный файл и версию. Отсутствие лицензии в metadata не разрешает свободное копирование проекта.

## Как применять в расчётах

1. **Мощность и приводы.** Определить полное сопротивление катамарана, взаимодействие винтов с корпусами, обороты и момент; затем инвертор, мотор, передачу и охлаждение. Для каждого рабочего режима записывать DC-ток, фазный RMS/peak, карту потерь и температуру. MAM17, OSEO и открытые платы не поставляют готовых численных входов для нашего HPM.
2. **Солнечная энергия и аккумуляторы.** Почасовой профиль PV брать из pvlib с маршрутом, сезоном и затенением. В энергетическом балансе учитывать MPPT, заряд/разряд, бытовые нагрузки, ИИ, связь и запуск кайта. FEEMS/RunFEEMSSim — кандидаты для независимой модели после проверки аналитических эталонов и сходимости шага. Их установка и работоспособность в ECONA пока не подтверждены.
3. **Сценарий с генератором.** Считать отдельно от базовой кайт–PV–АКБ схемы, с действительной характеристикой расхода, минимальной нагрузкой, стартами, охлаждением и массой. Каталог не утверждает ДГУ или запас топлива.
4. **Переходные процессы.** После выбора компонентов задать ёмкость DC-шины, предзаряд, отключения, ограничения BMS и скачки нагрузки. MarPowSim использовать как методический кандидат; наличие Octave не означает возможность открыть Simulink-модель.
5. **Масса и посадка.** Учитывать корпуса плат, контакторы, кабели, фильтры, насосы, охлаждение и крепления с координатами. Реальные массы передавать в Ship Weight/LoadCondition/SinkAndTrim/GZ; заданный предел осадки 0,53 м не повышается из-за нового оборудования.

Карта применения с входами и результатами — `research/marine-opensource/application-map.yaml`. Шаблон физических входов — `calculations/energy/marine-opensource/input-passport.yaml`. Неизвестные величины сохранены как `null`, чтобы название проекта не превращалось в неподтверждённую характеристику.

## Предлагаемое разделение управления

VCU — координатор приводов, EMS — управление энергией. Рассматривать их как детерминированный промежуточный уровень между локальным ИИ и отдельными контроллерами. Контуры тока инверторов, защита батареи и аварийные функции сохраняют самостоятельность.

```text
PV → MPPT → выбранная общая или секционированная DC-система ↔ АКБ/BMS
             ├→ инвертор слева  → HPM → передача → винт
             ├→ инвертор справа → HPM → передача → винт
             └→ DC/DC и приоритетное питание управления
Опциональная ДГУ → согласованное зарядное устройство/DC/DC → DC-система

Локальный ИИ → проверка команд → VCU/EMS → интерфейсы компонентов
Ручной приоритет и независимые аппаратные ограничения действуют отдельно
```

Общая шина в исходной схеме не гарантирует независимости двух движителей. Выбор секционирования, межсекционных соединений, развязки питания и CAN требует анализа общих отказов. CAN-протокол от одной лодки нельзя автоматически считать NMEA 2000 или соединять напрямую с Signal K.

Для будущих интерфейсов определить единицы, диапазоны, знак тяги, время измерения, период сообщения, timeout, heartbeat, приоритет ручного управления и подтверждение выполнения. При потере связи переход зависит от режима и возможности ручного управления; единственное универсальное действие «отключить всё» не назначается.

Зарядное напряжение полного банка, выбросы и рекуперация проверяются отдельно от номинала 72 В. Возможность рекуперации не означает возможность принять энергию при полном или холодном аккумуляторе. Гидрогенерация под кайтом добавляет сопротивление движению и не является бесплатным источником энергии.

## Программа проверки перед выбором

Сначала эталонные энергетические балансы и проверка размерностей; затем временная модель с ограничениями SOC/температуры и отказами связи. Для аппаратного кандидата нужны ревизия платы, схема, BOM, реальные диапазоны, охлаждение, испытания защиты и длительного режима. Совместимость и морская пригодность проверяются для конкретного комплекта.

Действующие исследования [Electrotransport](31_electrotransport_review.md), [системы энергетики](05_energy.md) и [выбор привода](06_motors.md) сохраняются.
